Hình 2.1: Quy trình thu thập dữ liệu chỉ số (Metrics Scrape) và trực quan hóa thời gian thực

1. Vì sao Observability là cốt lõi trong hệ thống Cloud?

Trong kiến trúc phân tán gồm nhiều máy chủ nhỏ lẻ như MiniCloud, người quản trị không thể trực tiếp SSH vào từng máy để kiểm tra lệnh top hay free -m. Thay vào đó, chúng ta cần một cơ chế giám sát tập trung tự động (Centralized Observability).

2. Mô hình Pull-Based của Prometheus

Khác với các hệ thống giám sát truyền thống bắt agent gửi dữ liệu về (Push), Prometheus hoạt động theo cơ chế Pull (Scrape). Định kỳ mỗi 15 giây, Prometheus sẽ chủ động gửi HTTP GET request đến các endpoint /metrics đã được khai báo: 

# Trích đoạn file prometheus.yml
global:
  scrape_interval: 15s

scrape_configs:
  - job_name: 'node-exporter'
    static_configs:
      - targets: ['monitoring-node-exporter-server:9100']

  - job_name: 'web-frontend'
    static_configs:
      - targets:
          - 'web-frontend-server:80'
          - 'web-frontend-server2:80'

3. Thiết kế Dashboard "System Health" trên Grafana

Grafana tại cổng 3000 kết nối vào Prometheus thông qua ngôn ngữ truy vấn mạnh mẽ PromQL. Dashboard tự động hiển thị 3 chỉ số then chốt:

  • CPU Utilization (%): Tính toán tỷ lệ CPU bận rộn bằng cách lấy 100% trừ đi lượng CPU ở trạng thái nghỉ (idle).
  • RAM Usage: Đo lường lượng bộ nhớ thực tế hệ thống đang phân bổ cho các tiến trình container.
  • Network Traffic (I/O): Theo dõi lưu lượng gói tin gửi và nhận (Transmit / Receive Bytes) qua card mạng cloud-net.
💡 Kết quả đạt được: Trạng thái của cả 2 mục node-exporter và web-frontend trên giao diện Prometheus Targets luôn hiển thị UP với màu xanh lá, chứng minh các luồng thu thập dữ liệu hoạt động ổn định và liên tục.
