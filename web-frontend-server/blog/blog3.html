Hình 3.1: Quy trình cấp phát JWT Bearer Token qua Direct Access Grants và xác minh tại Backend

1. Vì sao không dùng Session truyền thống trong Cloud?

Trong kiến trúc phân tán có cân bằng tải Round Robin (như Web 1 và Web 2), nếu dùng Session lưu trong RAM máy chủ thì khi request sau bị chuyển sang máy chủ khác, trạng thái đăng nhập sẽ bị mất ngay lập tức (Session State Inconsistency).

Giải pháp chuẩn công nghiệp là Stateless Authentication (Xác thực phi trạng thái) với chuẩn OpenID Connect (OIDC) và JSON Web Token (JWT) do Keycloak quản lý.

2. Mô hình Realm, Client & User trong Keycloak

  • Realm (realm_21110001): Phân vùng bảo mật cô lập chứa toàn bộ cấu hình người dùng và ứng dụng của dự án.
  • Client (flask-app): Đăng ký ứng dụng Backend với Keycloak, kích hoạt chế độ Direct Access Grants (Password Grant) phục vụ kiểm thử REST API qua CLI hoặc Postman.
  • Users (sv01, sv02): Hai tài khoản sinh viên được tạo tự động với mật khẩu an toàn password123.

3. Đoạn mã Python xác thực Token tại Flask Backend

# Trích đoạn endpoint /secure trong app.py
@app.route("/secure", methods=["GET"])
def secure_endpoint():
    auth_header = request.headers.get("Authorization", None)
    if not auth_header or not auth_header.startswith("Bearer "):
        return jsonify({"status": "unauthorized", "message": "Missing Bearer token"}), 401

    token = auth_header.split(" ")[1]
    try:
        # Giải mã Payload Base64URL của JWT Token
        payload_b64 = token.split(".")[1]
        payload_b64 += "=" * ((4 - len(payload_b64) % 4) % 4)
        payload = json.loads(base64.urlsafe_b64decode(payload_b64).decode("utf-8"))
        
        return jsonify({
            "status": "authenticated",
            "message": "Access granted to secure resource!",
            "user": {
                "preferred_username": payload.get("preferred_username"),
                "email": payload.get("email")
            }
        })
    except Exception as e:
        return jsonify({"status": "error", "message": f"Invalid Token: {str(e)}"}), 400
💡 Kết quả xác thực: Khi gửi kèm Header Authorization: Bearer <token> lấy từ Keycloak, endpoint /secure phản hồi mã 200 OK kèm thông tin định danh của chính sinh viên đó (username, email, roles).
